# Domain Scout Output Example

## 正确示例

用户输入：

```text
我想用 60 分钟判断 RAG 应用开发值不值得继续学。
我会一点 Python，想以后做企业知识库类产品，但不知道 RAG 是不是太难。
```

专家先问：

```text
先确认 3 件事：
1. 你学 RAG 是为了自己做产品原型，还是为了找工作/接项目？
2. 你现在能不能用 Python 调 API、读写文件？
3. 60 分钟后你更想得到判断、概念地图，还是一个能跑的小 demo？
```

用户补充：

```text
主要是做产品原型。我能用 Python 调 API，也能读写文件。
60 分钟后我想知道要不要继续学，并有一张地图。
```

输出：

```markdown
## 结论
继续学

一句话判断：RAG 应用开发值得你继续学，但下一步不要追复杂框架，先用最小 demo 验证“检索 + 生成”这条主线。

## 为什么
- 你的目标是企业知识库产品，RAG 正好解决“把私有资料接入问答”的问题，目标匹配度高。
- 你已经会 Python 调 API 和读写文件，能跨过最小实验门槛。
- 风险在于 RAG 很容易被框架和术语淹没，所以第一轮只学检索、切块、向量、召回、生成这几个节点。

## 第一张理解地图
| 节点 | 一句话解释 | 相关节点 | 状态 | 待核验 |
|---|---|---|---|---|
| 文档切块 | 把长文档拆成适合检索的小段 | 向量化、召回 | 未验证 | 切块策略需查具体框架文档 |
| 向量化 | 把文本变成可比较的数字表示 | 检索、向量库 | 未验证 | embedding 模型选择需核验 |
| 向量库 | 存放向量并支持相似度搜索 | 向量化、召回 | 未验证 | 具体产品能力需查官方文档 |
| 召回 | 从资料里找出最相关片段 | 文档切块、生成 | 未验证 | 召回质量评估方法需核验 |
| 生成 | 把召回片段交给模型组织答案 | 召回、提示词 | 未验证 | 模型能力和成本需核验 |
| 评估 | 判断答案是否准确、有依据 | 生成、召回 | 未验证 | 评估指标需进一步学习 |

## 小实验或练习反馈
- 建议小实验：准备 3 段短文本，手工选择最相关的一段，再让模型只根据这段回答一个问题。
- 真正理解了：如果你能解释“为什么先找资料再让模型回答”，说明你理解了 RAG 主线。
- 还只是照着做：向量化和向量库暂时可以先不深究。
- 主要卡点：如何判断召回内容是否真的相关。

## 下一步 90 分钟
只做这一件事：用 3 个本地文本片段做一个最小问答 demo，先不用复杂框架，只验证“问题 -> 找片段 -> 根据片段回答”。

## 需要核验
- 当前可用 embedding 模型、价格和限制。
- 所选向量库或框架的官方入门文档。
- 企业资料是否涉及隐私、权限和合规要求。
```

## 错误示例

```markdown
RAG 是 Retrieval-Augmented Generation 的缩写。下面是完整教程：
1. 机器学习基础
2. 深度学习基础
3. Transformer
4. 向量数据库
5. LangChain
6. LlamaIndex
7. 部署和运维
```

错误原因：

- 没有先问用户目标、基础和完成标准。
- 直接变成百科目录，没有判断是否值得学。
- 没有第一张 5-7 节点理解地图。
- 没有小实验或练习。
- 没有标注哪些信息需要核验。

## 完整输入到输出示例

输入：

```text
领域：提示词工程
目标：想知道它是否值得作为副业能力学习
背景：会写文章，不会编程
限制：不想学太多技术，希望能在内容工作中用起来
```

输出：

```markdown
## 结论
观察一下

一句话判断：提示词工程值得你用低成本试一轮，但暂时不建议把它当成独立副业能力长期押注。

## 为什么
- 它能直接服务你的内容工作，短期上手成本低。
- 但“会写提示词”单独作为副业卖点不够硬，最好和内容策划、资料整理、自动化流程结合。
- 你不想学太多技术，所以第一阶段应避开复杂工具链，只验证它能否提升你的具体产出。

## 第一张理解地图
| 节点 | 一句话解释 | 相关节点 | 状态 | 待核验 |
|---|---|---|---|---|
| 任务定义 | 把“帮我写”改成清楚目标和约束 | 输出评估 | 未验证 | 无 |
| 上下文 | 给模型足够背景材料 | 资料整理 | 未验证 | 隐私材料需脱敏 |
| 示例 | 用样例告诉模型什么叫好 | 输出评估 | 未验证 | 无 |
| 约束 | 限制语气、长度、格式和边界 | 任务定义 | 未验证 | 无 |
| 迭代 | 根据输出继续修改要求 | 输出评估 | 未验证 | 无 |
| 输出评估 | 判断结果能不能直接用 | 任务定义、迭代 | 未验证 | 评估标准需结合真实工作 |

## 小实验或练习反馈
- 练习 1：把一篇旧文章改写成 3 种标题风格，并比较哪种更适合你的读者。
- 练习 2：给同一任务分别写“模糊提示词”和“带背景/约束/示例的提示词”，比较结果。
- 练习 3：把一次不满意输出改 3 轮，记录每轮改了什么。
- 真正理解了：如果你能解释为什么“背景 + 约束 + 示例”会影响输出，说明你抓住了主线。
- 还只是照着做：评估标准可能还不清晰。
- 主要卡点：如何判断输出质量，而不是只看它是否顺眼。

## 下一步 90 分钟
只做这一件事：选择一个真实内容任务，做 3 轮提示词迭代，并记录每轮带来的具体改进。

## 需要核验
- 如果要把它作为副业，需要核验真实客户是否愿意为“提示词”本身付费。
- 如果处理客户材料，需要核验隐私和授权边界。
```
